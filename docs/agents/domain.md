# Domain docs

## Before exploring

Read `Main_Culture_andETHOS.md` before product, design, or architecture decisions, as required by `AGENTS.md`.

Read the root `GLOSSARY.md` if present and relevant decisions in `docs/adr/` before exploring a domain area. If these do not exist, proceed silently. Create them lazily through domain modeling when terms or decisions are resolved.

## Layout

This repository uses one root `GLOSSARY.md` and root `docs/adr/` directory. No per-context glossaries or glossary map are required.

## Vocabulary and decisions

Use the glossary's terms in issues, proposals, hypotheses, and tests. For a missing concept, reconsider invented language or note a real gap for domain modeling.

Surface conflicts with existing ADRs explicitly, naming the ADR and why it may need revisiting. Resolve decisions consistently with the governing product direction in `Main_Culture_andETHOS.md`.
