# Hosted research execution and readable case studies

## Job and context

An engineer should understand what each case tested, what actually happened, what a model can support, and what to do next. The previous entry page led with run tables and raw diagnostics. The earlier Prime attempt used production qualification requirements for an exploratory literature assessment, preventing use of the already configured hosted model.

## Decision

Reuse the existing Prime SDK, saved Modal model registry and provider authentication, scientific model tools, gateway trace/budget ledger, technology-transfer workbench, engineering proposals and persistent companion. A scoped research-profile option is passed only by fermentation exploratory assessments. No production qualification, global unqualified routing, separate agent framework or new chat interface is introduced.

The case-study route now presents four selectable narratives: Sulfolobus, Pichia, the fictional factory investigation with Sanofi historical context, and simulation-derived IndPenSim. The first two show recorded deterministic results with a source hash. Live exploration opens the existing transfer component. The legacy benchmark/source inspector remains available. Discussion attaches context to the existing companion; retrospective displayed answers are explicitly unsuitable for blinded evaluation inputs.

The simple alternative was to restyle the existing diagnostic tables. That retained the burden of interpreting a benchmark export before understanding the engineering question. A larger alternative was a new case dashboard or agent workspace. That duplicated established tools and navigation. The selected change reorganizes presentation and reuses the existing interactive workbench.

## Four-pillar checks and trade-offs

- **Start:** the first useful scientific comparison loads without configuring or running a model. Hosted authentication reuses local configuration.
- **Trust:** measurements, empirical predictions, modeled dollars and evidence gaps are labeled separately. Citations, assumptions, sensitivity, frozen split and version hashes remain inspectable. The schematic does not imply reported geometry.
- **Act:** scenario exploration executes the deterministic API; its result survives switching into review. Recommendations remain distinct from approval and equipment execution.
- **Adopt:** routes and services remain in the existing OS. The full diagnostic archive is one inspection step deeper; this is a deliberate trade-off for a readable default page.

Observable measures are whether a useful comparison is visible without opening diagnostics, whether source and parameter inspection remains possible, whether scenario changes execute real calculations, whether review retains its calculation basis, and whether the layout works at 390 px. These are functional observations, not measured human time savings or proof of improved user comprehension.
